# OTP → Parent PIN → Biometric navigation repair

21 October 2026. Navigation-only repair inside existing V2. No screen, component, copy, spacing or color changes.

## Root causes reproduced

Five stored-action checks failed before repair:

1. Registration processing1461:474 wrote NewParentConsented1650:475=false in both normal/reduced-motion OTP-entry branches. OTP's downstream PIN gate consequently remained false even after actual required consents and verification success.
2. PIN toolbar Back1650:528 returned to OTP with Verified=true and ButtonState=Disabled. Re-verification was blocked. The corresponding Escape action on PIN1650:502 needed the same recovery.
3. OTP's review-only Success choice1612:2119 reset new-parent eligibility unconditionally, losing the registration context.

Review clones also inherited identical “Final Authentication — Approved Login” start labels, and timeout overlays were listed as flow starts. This made launching the intended journey confusing.

- Registration's two eligibility writes now derive from the existing four explicit required consent booleans: Terms1459:244, Privacy1459:242, Adult1459:246 and ChildData1459:248. Optional consent is not a gate. No agreement is fabricated or preselected.
- Existing OTP verified/new-parent gate and PIN initialization remain intact. Successful Registration OTP now routes to confirmed PIN1650:502 automatically, without review switches.
- PIN Back/Escape preserves the existing confirmation-to-setup behavior. When leaving setup for OTP, it clears OTP Verified/Busy/transient feedback, sets operation=verify and restores the button according to existing Ready/Locked state. - Success review choice derives eligibility from actual registration origin plus required consents, instead of resetting it indiscriminately.
- Biometric offer, guard, loading response, error/retry, Skip/Cancel and PIN fallback were already connected correctly; they were verified and preserved.
- Removed inherited review/timeout start entries within010/012 and renamed main OTP/PIN entries. Added an explicit Registration start. Original Splash/Login/Intro/legal start entries are preserved.

Figma actions use supported flat conditions. No new variables, frames or components were created. Mutated nodes:1461:474,1612:2119,1650:528,1650:502 and page928:2 flow-start metadata.
