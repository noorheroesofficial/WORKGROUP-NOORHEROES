## Approved content and behavior

User approved:
- Set your Parent PIN
- Choose a 4–6 digit PIN to protect the Parent area & manage screen time
- Confirm your Parent PIN
- Re-enter your PIN to confirm.
- Continue
- Save PIN
- PINs don’t match. Please try again.
- Enter a 4–6 digit PIN.

The4/5/6 length choices are shown before confirmation;6 is the initial fixture choice. No strength judgment, fabricated security claim or fingerprint-instead bypass is shown. Biometric enrollment belongs after successful PIN setup and only when hardware/enrollment availability allows it.

| Action/state | Prototype result |
|---|---|
| Choose4/5/6 | Reset both masked counts; cap input at chosen length |
| Tap numeric keypad / desktop0–9 | Increment masked entry count; never capture a PIN value |
| Delete / Backspace | Remove one masked position |
| Continue after complete Set pass | Confirmation; Set count retained; Confirm count starts empty |
| Length control during confirmation | Disabled, keeping the selected length visible |
| Save PIN with mismatch fixture | Clear only Confirm count; preserve Set count; inline approved error |
| Type again after mismatch | Clear feedback and continue confirmation |
| Save PIN with matching fixture | Fixed-size primary light-dot loader, duplicate-submission/input guard |
| Save success | Stop loader, clear both counts, mark simulated saved state; future exit remains unmapped |
| Offline/API failure | Restore action; retain both counts; shared Snackbar with Retry/Dismiss |
| Timeout |2s processing +8s hold; restore retry after10s |
| Back from confirmation | Return to Set pass with Set count retained |
| Back from first pass | Clear counts and return to existing OTP screen |
| Back after saved fixture | Return to existing OTP; no editing of a saved PIN without a future verified-reset flow |

The description has a stable40px slot across both passes. Confirmation/mismatch/saving/offline examples use the same390×844 size. Mismatch expands the content only as needed and fits within the viewport.

## Prototype limits and production requirements

**This prototype intentionally stores only counts and controlled outcomes, not PIN values. Match/mismatch is simulated, not a comparison of entered digits.** Do not use real credentials for review.

Production must perform actual Set/Confirm equality, secure hashing/storage, server-success-before-local-store ordering, immediate clearing of PIN material, verified reset authorization, session restoration and accessibility announcements through the documented existing security architecture. The Figma artifact does not implement those systems.

Network,10s timeout and recovery are controlled fixtures; there are no production requests. Figma does not provide a native keyboard/OS biometric implementation here. No claim of real-device, screen-reader or Present playback verification is made.

Biometric Enrollment013 and Add Child014 remain uncreated/unmapped. On successful production save, eligible hardware may lead to013; unavailable hardware must skip it entirely and go to the confirmed Add Child destination. Those connections await their screens; no placeholder or wrong substitute was added. The local interactive companion was not modified in this task.
