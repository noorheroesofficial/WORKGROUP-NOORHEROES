## Review controls

- Start from either existing Login or Registration, or open the main OTP frame.
- Tap a cell for mobile keypad input. Tap outside the keypad or its down arrow to dismiss it.
- Desktop keys0–9, Backspace, Enter are wired. P enters a fictional sample code.
- D opens review-only scenario controls: success, incorrect, expired, offline, API error, timeout, delivery failure, lockout and reset.
- For network recovery, N on the Snackbar selects the simulated recovered response; Retry processes again.
- Lockout review case sets five prior invalid responses; the next submission is blocked.
- Reset is a review fixture, not a production bypass.
- Existing reduced-motion variable1389:3045 selects Still loader phase and instant incoming navigation. Normal forward navigation uses240ms ease-out dissolve.

## Deliberate boundaries and open requirements

1. **Success exit pending:** Parent PIN Setup, Profile Picker, and a confirmed post-verification consent destination are not approved V2 screens. No placeholder route or duplicate consent route was created. The PRD's new/returning/session-state routing remains an implementation requirement.
2. **Fallback pending:** Delivery failure enables immediate resend and safe recovery feedback. Screen011/fallback channel choice remains unmapped until approved; ordinary incorrect-code errors never route to fallback.
3. **Controlled fixtures:** The outcome selector simulates server responses. Any six digits can reach the selected simulated response; this is not identity validation.
4. **Server time:**30s resend and15s lockout are demonstration values, not declared server policy. Production must use authoritative server time, progressive policy, risk logging and multiple simultaneously valid OTP TTLs.
5. **Privacy:** Recipient is fully masked as•••. Native Figma cannot dynamically substring-mask arbitrary identifiers; production must show the safely masked actual recipient. No raw identifier is exposed here.
6. **Input/persistence:** Custom keypad and desktop digit entry work through native prototype actions. P is a paste simulation; real clipboard, SMS autofill, screen-reader announcements and OS keyboard are not implemented by Figma. Variables retain state only in the prototype session, not durable app restoration.
7. **Live verification:** Present playback was unavailable under current access permissions and was not attempted again. No real-device, production-auth, real network, provider failover or runtime accessibility verification is claimed.
8. Screen009 rollback remains intact; no consent-detail work was reintroduced. Local companion prototype was not changed by this screen task.
9. Only the requested390×844 viewport was designed. No extra device-size or translated UI variants.
