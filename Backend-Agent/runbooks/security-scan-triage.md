# Runbook: Security Scan Triage & Non-Bypassable CI Gates

**Document ID:** `docs/runbooks/security-scan-triage.md`  
**Related Blueprint:** `Development_Blueprints.Phase1_Infra_Config.CI_CD.07-ci-pipeline-security-scan-stages`  
**Audience:** Backend Engineers, Security Leads (`@noorheroes/security-leads`), DevOps Engineers

---

## 1. Overview & Architecture

NoorHeroes enforces a **non-bypassable security baseline** at CI Stage 8. Every pull request targeting `main` must clear static application security testing (SAST), dependency vulnerability scanning, container image scanning, and secret scanning before merge.

Branch protection rules on `main` enforce `enforce_admins=true` ("Include administrators"). No role or repository administrator can bypass a failing security check.

```
PR Opened / Pushed
       │
       ├─► sast-bandit (Python AST security rules)
       ├─► sast-semgrep-backend (OWASP Top 10, Security Audit)
       ├─► dependency-scan-backend (pip-audit against installed lockfile)
       └─► container-scan-backend (Trivy OS & package scanner)
               │
               ▼
       backend-security-gate (Aggregator Status Check — REQUIRED ON MAIN)
```

---

## 2. Security Tooling & Severity Threshold Matrix

Every scanner's raw output is triaged by `.github/scripts/security_gate.py` against the following strict threshold table:

| Scanner | Tool | Merge Blocking Condition | Non-Blocking (Warn Only) | Ignored |
|---|---|---|---|---|
| **Python SAST** | Bandit | `severity=HIGH` at `confidence>=MEDIUM` | `severity=MEDIUM` | `severity=LOW` |
| **Multi-Language SAST** | Semgrep | `severity=ERROR` / `level=error` | `severity=WARNING` | `severity=INFO` / `NOTE` |
| **Backend Dependencies** | `pip-audit` | CVSS **≥ 7.0**, or **Unscored Advisory** (Fail-Closed) | CVSS 4.0 – 6.9 | CVSS < 4.0 |
| **Admin-Web Dependencies**| `pnpm audit` | `high` or `critical` | `moderate` | `low` / `info` |
| **Mobile Dependencies** | Dependency-Check | CVSS **≥ 7.0** (`failBuildOnCVSS = 7.0`) | CVSS 4.0 – 6.9 | CVSS < 4.0 |
| **Container Images** | Trivy | `CRITICAL` or `HIGH` **with available fix** | `MEDIUM`, `LOW`, or `CRITICAL`/`HIGH` with **no fix yet** (`--ignore-unfixed`) | None (all uploaded to SARIF) |

## 3. How to Read a Failed Security Check

When a PR check fails:
1. Open the GitHub Actions run and locate the failing job: `sast-bandit`, `sast-semgrep-backend`, `dependency-scan-backend`, or `container-scan-backend`.
2. Inspect the **GitHub Step Summary** generated by `security_gate.py`:
   - Lists exact CVE / GHSA / Bandit Rule IDs.
   - Shows affected target file, package name, or container layer.
   - Displays whether fixes are available.
3. Open **GitHub Security → Code scanning** tab to view the rich SARIF finding context with line annotations and CWE explanations.

## 4. Fix vs. Waive Decision Framework

### 4.1 Preferred Action: Remediation (Fix)
- **SAST Findings**: Refactor code to eliminate insecure pattern (e.g. use parametrized SQL, avoid shell execution, use `secrets` module instead of `random`).
- **Dependency Findings**: Bump the affected package in `pyproject.toml` or `requirements.txt`.
- **Container Findings**: Update the base Docker image tag in `Dockerfile` to the latest security patch.

### 4.2 Prohibited Actions
- ❌ Adding inline `# nosec` or `# nosemgrep` comments to bypass CI without approval.
- ❌ Using `.trivyignore` or undocumented suppression files.
- ❌ Disabling required status checks in branch protection settings.

## 5. Security Waiver Protocol (`.github/security-waivers.yml`)

The **only legitimate method** to unblock a finding that is a verified false positive or an accepted, time-boxed upstream risk is registering an entry in `.github/security-waivers.yml`.

### 5.1 Waiver File Schema
```yaml
version: 1
waivers:
  - id: WAIVER-2026-001
    tool: pip-audit                       # bandit | semgrep | pip-audit | pnpm-audit | dependency-check | trivy
    finding_id: CVE-2026-XXXXX            # CVE id, GHSA id, or tool rule id (e.g. B602)
    scope: "backend — starlette package"  # Substring match against file path or package name
    justification: "Transitive pin by FastAPI 0.111.1; reverse proxy normalizes Host headers."
    approved_by: "@noorheroes/security-leads"
    created_date: "2026-08-20"
    expires_date: "2026-09-19"            # Mandatory — must satisfy max duration limit
    ticket: "SEC-142"                     # Remediation tracking issue
```

### 5.2 Maximum Allowed Duration by Severity
| Severity | Maximum Waiver Window |
|---|---|
| **Critical** | 30 days |
| **High** | 90 days |
| **Medium** | 180 days |
| **Trivy Unfixed Upstream** | 30 days (auto-renewable upon nightly scan verification) |

### 5.3 Approval Enforcement
`/.github/security-waivers.yml` is protected in `.github/CODEOWNERS`:
```
/.github/security-waivers.yml @noorheroes/security-leads
```
No pull request modifying the waiver file can merge without approval from `@noorheroes/security-leads`.

---

## 6. Scheduled Nightly Re-Scans (`security-nightly-rescan.yml`)

1. **Daily Execution**: Runs at 03:00 UTC against the latest `main` container images and dependency lockfiles.
2. **Post-Merge Zero-Day Detection**: If a CVE is disclosed for an already-merged dependency, the workflow does not break historical commits; it files an automated GitHub Issue labeled `security-nightly` assigned to `@noorheroes/security-leads`.
3. **7-Day Expiry Warnings**: The nightly run inspects `.github/security-waivers.yml` and warns in advance about any waiver expiring within 7 days.

---

## 7. Handling External Vulnerability DB Outages (Fail-Closed Policy)

If an external vulnerability database (PyPA, NVD, Trivy DB) experiences an outage:
1. **Fail-Closed Guarantee**: CI jobs will fail rather than silently granting green passes on unchecked code.
2. **Escalation**:
   - Check status pages: GitHub Status, PyPI Status, NVD Feed Status.
   - Once upstream service recovers, re-run failed jobs via GitHub Actions `Re-run failed jobs` button.
   - For emergency deployments during prolonged global upstream outages, contact `@noorheroes/security-leads` to issue an emergency time-boxed waiver.
